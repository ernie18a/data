On each timer check, estimate the server-day starting balance as current account balance minus the sum of profit, commission and swap on today's closing and reversing deals; if history is unavailable, use the current balance. Calculate drawdown as (starting balance minus current equity) divided by starting balance, or zero if the starting balance is not positive. Once the hard drawdown threshold is reached, latch the breach for the lifetime of the program instance and stop evaluating risk rules. If automatic closure is enabled, attempt to close every open position and delete every pending order, retrying each failed request up to the configured limit. Optionally remove the program after the breach. Before a hard breach, if mitigation is enabled and drawdown is at or above the soft threshold but below the hard threshold, and the mitigation cooldown has elapsed, select the open position with the lowest profit plus swap, provided that value is negative. Close the configured fraction of its volume, rounded down to the instrument's volume step; if the rounded volume is below the minimum, close the entire position. Retry failed close requests up to the configured limit. Reset the mitigation cooldown after each eligible attempt, even if no losing position exists or the close fails.
