Memory Sequence
is a same-symbol multi-chart time-window sync indicator. One chart is the host. Every other chart of that symbol is a slave. The host publishes one candle’s open-to-close window, and every slave draws that window and scrolls it into view. It does not plot its own series (indicator_plots 0). It drives chart objects, chart navigation, and candle colors. Charts talk through terminal global variables plus EventChartCustom (event id 222). No DLL.
This indicator is purposed for those who plan to review a specific moment in price action history.

What it is for
Use it when several charts of one symbol are open at different timeframes and you want one click to mark the same moment on all of them.
Typical setup: H1 (or whichever timeframe you read structure on) is the host. M1, M5, M15, H4, D1 of the same symbol are slaves. Click a candle on the host. Each slave gets:
a solid vertical line at the host candle’s open time
a dotted vertical line at the host candle’s close time
an optional horizontal line at that candle’s close
an optional filled rectangle covering that time span, with high/low taken from the bars on that chart inside the span
On a lower timeframe the box covers every bar inside the host candle. On a higher timeframe it lands on the bar that contains that window. That is the useful read: the host picks the idea, the slaves show how that idea looks in finer or coarser structure.
Host mouse move snaps a crosshair to the candle under the cursor and draws a hover box. A click publishes that candle and freezes follow-the-live-bar until you click the live candle again. With
HostLockToLatest
and
AutoFollowHostBar
, a selection that is already the live bar keeps publishing each new host candle.
Attach starts at maximum zoom (
CHART_SCALE = 5
). After that, the mouse wheel can zoom out. Candle mode is forced back to candlesticks, bodies indigo, wicks chartreuse.
Exactly one chart per symbol should have
IsHost = true
. The host deletes the shared global variables on remove, so slaves go quiet when the host is taken off.

How the code is arranged
Startup (
OnInit
) builds the global-variable names from the chart symbol, forces candles and colors, applies zoom, creates the lines, box, crosshair, corner label, and a large centered timeframe watermark. The host immediately publishes bar 0. A slave reads whatever the host already stored. A 200 ms timer starts.
The host publishes in
PublishHostPick
. It stores open time, open time plus one host-period, close price, host period, and a rising sequence number. Then it paints its own chart and walks every open chart with
ChartFirst
/
ChartNext
, applying the window only where the symbol matches.
ApplyWindowToChart
is the slave (and host) painter. It creates the objects if missing, places the two vertical lines, the price line, and the rectangle. The rectangle’s high/low come from
iBarShift
plus a high/low scan across the bars inside the window, so a higher-timeframe chart is not asked to draw a one-bar host range it does not have. Navigation uses
ChartNavigate(CHART_END, …)
so the newer edge of the window sits near the right. If the host is tick-locked, that chart skips navigation and keeps autoscroll.
Slaves pick up changes three ways: the 200 ms timer,
OnCalculate
on a new tick, and custom event 222.
ApplySyncState
reads the globals and skips work if time, end, price, period, sequence, and the drawn line already match.
Host mouse move only updates the crosshair and hover box. Host click resolves x/y to a bar, clears live-follow memory, and publishes that bar’s open time and close. Chart change (resize, timeframe switch, mode change) restores candle colors, recenters the timeframe label, and reapplies sync.
OnDeinit
kills the timer, deletes this chart’s objects, and, on the host only, deletes the five global variables.
Practical limit:
sync is same-symbol only, terminal-local, and depends on one live host. Two hosts on the same symbol will overwrite each other. A slave opened before any host has published has nothing to draw until the host attaches or clicks.
